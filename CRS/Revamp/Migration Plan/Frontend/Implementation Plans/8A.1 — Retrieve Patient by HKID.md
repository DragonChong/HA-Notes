## Overview

This task wires the HKID field on the Registration Keys Panel to the patient retrieval workflow. When a valid HKID is entered, the system calls `lis-patient-svc` to retrieve matching local patient records. If PMI is configured, the user may also switch to PMI records. The selected episode populates the Patient Demographics panel and moves focus to Req No.

This plan covers:
- API integration for local patient lookup (`/api/lis/getPatientsByHkid`)
- API integration for PMI patient lookup (`/api/v2/getHkpmiPatientbyEnc`)
- `SelectEpisodeDialog` component (local list and PMI list modes)
- Post-selection field population and state transitions
- PMI unavailability fallback (Message 4274 + Message 687)

## State Design

Extend `RegistrationScreenState` (defined in 2.0.C) with patient retrieval state:

```typescript
interface PatientRetrievalState {
  status: 'idle' | 'loading' | 'episode-selection' | 'loaded' | 'error';
  hkid: string | null;
  localEpisodes: PatientEpisodeVo[];
  pmiEpisodes: PatientEpisodeVo[];
  pmiLoading: boolean;
  pmiAvailable: boolean;          // from Hub BFF config
  pmiUnavailableError: boolean;   // set true when PMI call fails
  selectedEpisode: PatientEpisodeVo | null;
  dialogMode: 'local' | 'pmi';
}
```

`screenMode` transitions driven by this state:
- `idle` → lookup starts → `loading`
- `loading` → records returned → `episode-selection` (dialog opens)
- `episode-selection` → episode selected → `loaded` → `screenMode: 'patient-ready'`
- `episode-selection` → dialog closed without selection → `idle`

## Hook: `useRetrievePatientByHkid`

Encapsulates all retrieval logic, keeping `SelectEpisodeDialog` and `RegistrationKeysPanel` as pure presentational consumers.

```typescript
function useRetrievePatientByHkid(options: {
  pmiAvailable: boolean;
  onPatientLoaded: (episode: PatientEpisodeVo) => void;
  onCreateNewPatient: (hkid: string) => void;   // triggers 8A.3
  onShowMessage: (code: number) => void;         // log monitor messages
}): {
  state: PatientRetrievalState;
  handleHkidConfirmed: (hkid: string) => void;
  handlePmiListClick: () => void;
  handleEpisodeSelected: (episode: PatientEpisodeVo) => void;
  handleDialogClose: () => void;
  handleGenerateComputerEncounter: () => void;
}
```

### `handleHkidConfirmed(hkid)`

1. Set `status: 'loading'`, store `hkid`.
2. Call `POST /api/lis/getPatientsByHkid` with `{ hkid }`.
3. On success: set `localEpisodes`, `status: 'episode-selection'`, `dialogMode: 'local'` — dialog opens.
4. On error: set `status: 'error'`, display error on log monitor.

### `handlePmiListClick()`

1. Set `pmiLoading: true`.
2. Call `POST /api/v2/getHkpmiPatientbyEnc` with `{ hkid }`.
3. On success: set `pmiEpisodes`, `pmiLoading: false`, `dialogMode: 'pmi'`.
4. On failure: set `pmiLoading: false`, `pmiUnavailableError: true`, show Message 4274, prompt Message 687.

### `handleDialogClose()` (from local mode Close ✕)

Implements **Close Indicator Behaviour** (Scenario 3):

1. If `pmiAvailable`:
   a. Call `POST /api/v2/getHkpmiPatientbyEnc`.
   b. If PMI records found → switch `dialogMode: 'pmi'`, update episode list.
   c. If PMI records empty → show Message 687 ("Create new Encounter case?").
      - Yes → `onCreateNewPatient(hkid)`.
      - No → close dialog, `status: 'idle'`.
   d. If PMI call fails → show Message 4274, then Message 687. Same Yes/No branching.
2. If `!pmiAvailable`: close dialog, `status: 'idle'`.

### `handleEpisodeSelected(episode)`

1. Set `selectedEpisode`, `status: 'loaded'`.
2. Call `onPatientLoaded(episode)`.
3. Close dialog.

## Post-Selection: Field Population

`onPatientLoaded` in the parent `RegistrationPage` / `useRegistrationState`:

```typescript
function applyPatientToScreen(episode: PatientEpisodeVo, dispatch: Dispatch) {
  dispatch({
    type: 'PATIENT_LOADED',
    payload: {
      encounterNo:   episode.encounterNo,
      name:          episode.name,
      chineseName:   episode.chineseName,
      sex:           episode.sex,
      dob:           episode.dob,
      ageUnit:       episode.ageUnit,
      locHospital:   episode.patientHospital,
      locSpecialty:  episode.unit,
      locWard:       episode.location,
      bed:           episode.bed,
      admitted:      episode.admissionDate,
      category:      episode.category,
      mrn:           episode.mrn,
      race:          episode.race,
      payCode:       episode.payCode,
    }
  });
}
```

The `PATIENT_LOADED` reducer also:
- Sets `screenMode: 'patient-ready'` — all patient demographic fields become dimmed (`disabled={true}`)
- **Category exception:** remains editable when `isNewPatient && demographicsEditingAllowed && category === ''`
- Populates `encounterNo` in the Keys Panel

**Focus after load:** move focus to `Req No.` field. Implement via a `useEffect` watching `screenMode === 'patient-ready'` that calls `reqNoRef.current?.focus()`.
