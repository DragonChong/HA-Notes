# Theme Handling Across MFE Apps

> [!warning] Active Investigation
> CMS `TextField` (`@cmschassis/react-ui`) renders with broken styling (blue fill, no outlined border, inflated height ~74px) in `lis-request-app` dev. Root cause not yet confirmed. This note documents the current setup across all five apps as a baseline for diagnosis.

## Overview

Each plugin app is responsible for its own theme and Emotion cache setup. The shell (`lis-hub-app`) provides a `lisBaseThemeLight/Dark` exported from `@lis/lis-hub-lib`, which all apps import. The CMS design system provides its own theme tokens via `BasicThemeLight`/`BasicThemeDark` from `@cmschassis/react-ui`.

The key architectural tension: `@cmschassis/react-ui` bundles its **own** copies of `@emotion/react`, `@emotion/styled`, and `@mui/material` as regular `dependencies` (not `peerDependencies`). This means every plugin works with **two** separate Emotion/MUI instances: one from the app bundle, one from the CMS component bundle.

## `lis-hub-lib` — Theme Source

**File:** `src/lib/components/Theme/theme/index.ts`

```ts
export const lisBaseThemeLight = createTheme(BasicThemeLight, {
  breakpoints,
  spacing: (factor) => `${factor * 1}px`,
  typography,
  components,  // plain-object overrides for MuiButton, MuiOutlinedInput, MuiTextField, MuiSelect, etc.
});

export const lisBaseThemeDark  = createTheme(BasicThemeDark, { ... });
export const lisBaseTheme      = createTheme(BasicThemeLight, { ... }); // alias, same as lisBaseThemeLight
```

### ⚠️ Critical: `components` block drops CMS function overrides

`BasicThemeLight.components.MuiTextField.styleOverrides.root` is a **callback function** generated by `getMuiTextFieldTheme()`. It dynamically sets `backgroundColor`, `borderRadius`, and fieldset border colours based on `ownerState.size`.

MUI's `createTheme` uses `deepmerge` internally. `deepmerge` **cannot merge a function with a plain object** — it replaces the function. The LIS `components` block provides a plain-object `MuiTextField.styleOverrides.root`, so after `createTheme(BasicThemeLight, { components })`:

```
lisBaseThemeLight.components.MuiTextField.styleOverrides.root
  = LIS plain object   ← CMS getMuiTextFieldTheme() callback is GONE
```

As a result, any app using `lisBaseThemeLight/Dark` as its theme base will render CMS `TextField` without outlined border, background fill, or border-radius.

**`lis-hub-lib` demo** (`src/App.tsx`) wraps in `ThemeProvider theme={lisBaseThemeLight}` with no `CacheProvider`. CMS `DatePicker` inside the demo appears broken in the same way but is not compared against the design spec, so it goes unnoticed.

## `lis-crs-common-app` (CRS Level-1 Remote, port 3010)

### `view-handler.tsx`
```tsx
// Scoped Emotion cache
const emotionRoot = document.createElement("style");
element.appendChild(emotionRoot);
const cache = createCache({ key: pluginId.toLowerCase(), container: emotionRoot, speedy: false });

// React tree
root.render(
  <React.StrictMode>
    <CacheProvider value={cache}>      // ✅ cache IS applied to the tree
      <ThemeWrapper>
        {React.createElement(component, props)}
      </ThemeWrapper>
    </CacheProvider>
  </React.StrictMode>
);
```
- `pluginId` = `"LisCrsCommonApp"` → cache key = `"liscrscommonapp"`
- Cache container is appended **inside `element`** (the Hub-provided DOM node)

### `ThemeWrapper.tsx`
```tsx
import { BasicThemeLight, BasicThemeDark } from '@cmschassis/react-ui';
// Subscribes to cms.api.preference for light/dark mode
return <ThemeProvider theme={theme === 'Light' ? BasicThemeLight : BasicThemeDark}>
  {children}
</ThemeProvider>;
```
- Uses `BasicThemeLight`/`BasicThemeDark` **directly** — preserves the CMS `getMuiTextFieldTheme()` function
- Subscribes to theme preference correctly

### `craco.config.js` — Module Federation shared
```js
shared: {
  react:       { singleton: true, requiredVersion: "18.2.0" },
  "react-dom": { singleton: true, requiredVersion: "18.2.0" },
  "emotion/react":   { singleton: true },  // ⚠️ MISSING @ prefix
  "emotion/styled":  { singleton: true },  // ⚠️ MISSING @ prefix
}
```
> [!bug] Missing `@` prefix on Emotion singletons
> `"emotion/react"` is not the same as `"@emotion/react"`. Webpack treats the unrecognised string as an unresolved module and falls back to each app bundling its own copy. The singleton constraint has **no effect**. The correct keys are `"@emotion/react"` and `"@emotion/styled"`.

```tsx
// Bug: setTheme() is called on preference change but lisBaseTheme is always used
return <ThemeProvider theme={lisBaseTheme}>{children}</ThemeProvider>;
```
- Theme mode subscription is **broken** — always uses `lisBaseTheme` regardless of dark/light state
- Uses `lisBaseTheme` which has the CMS function problem (see lis-hub-lib section above)

### `ThemeAwareRoot.tsx` (new, under investigation)
```tsx
import { BasicThemeDark, BasicThemeLight } from '@cmschassis/react-ui';
// Subscribes to cms.api.preference for light/dark mode correctly.
const cmsBase = themeMode === 'dark' ? BasicThemeDark : BasicThemeLight;
return <ThemeProvider theme={buildRegistrationTheme(cmsBase, fontSize)}>
  <FontSizeContext.Provider value={fontSizeVariant}>
    {children}
  </FontSizeContext.Provider>
</ThemeProvider>;
```
- Uses `BasicThemeLight/Dark` directly — intended to preserve CMS function
- Provides `FontSizeContext` for 14px / 18px font-size variant at screen-open time

### `theme-builder.ts`
```ts
export function buildRegistrationTheme(base: Theme, fontSize: 14 | 18): Theme {
  return createTheme(base, {
    components: {
      MuiInputBase:    { styleOverrides: { root: { fontSize }, input: { paddingTop, paddingBottom } } },
      MuiInputLabel:   { styleOverrides: { root: { fontSize }, shrunk: { fontSize } } },
      MuiFormLabel:    { styleOverrides: { root: { fontSize } } },
      MuiMenuItem:     { styleOverrides: { root: { fontSize } } },
      MuiButton:       { styleOverrides: { root: { fontSize } } },
      MuiAutocomplete: { defaultProps:   { size: 'small' } },
      // MuiTextField.defaultProps.size intentionally omitted
    },
  });
}
```
> [!warning] `MuiInputBase` overrides may conflict with CMS padding rules
> `getMuiTextFieldTheme()` sets `"& .MuiOutlinedInput-input": { padding: 0 }` on the `MuiTextField` root slot. The `MuiInputBase.input` padding added here (`paddingTop/Bottom: 6`) is injected as a **later** Emotion class at equal specificity — it wins over the CMS `padding: 0`, stacking with the wrapper's `12px` padding and producing the ~74px height. Needs further testing.

## Known Issues

### Issue 1 — `emotion/react` singleton key missing `@` prefix
**Affected:** `lis-crs-common-app`, `lis-request-app`, `lis-aps-app`

The correct Module Federation shared key is `"@emotion/react"` and `"@emotion/styled"`. Without the `@`, webpack does not resolve these to singleton modules and each app bundles its own Emotion copy.

**Fix:** In all affected `craco.config.js` files:
```js
"@emotion/react":  { singleton: true },
"@emotion/styled": { singleton: true },
```

### Issue 2 — `lisBaseThemeLight` drops CMS `getMuiTextFieldTheme()` function
**Affected:** Any app using `lisBaseTheme`/`lisBaseThemeLight`/`lisBaseThemeDark` as the MUI theme base when rendering CMS `TextField`/`DatePicker`/`TextArea`.

`createTheme(BasicThemeLight, { components: lisComponents })` replaces the CMS function-based `MuiTextField.styleOverrides.root` with a plain object because `deepmerge` cannot merge a function with an object. The result: no outlined border, no background colour, no border-radius on CMS-styled inputs.

**Fix:** Use `BasicThemeLight`/`BasicThemeDark` directly as the MUI theme if CMS components are in the tree. If LIS typography/spacing overrides are also needed, apply them via a separate nested `ThemeProvider`.

### Issue 3 — `lis-aps-app` `CacheProvider` not applied
**Affected:** `lis-aps-app` only.

The scoped Emotion cache is created but never passed to `CacheProvider`. All styles go into the global Emotion style sheet. The empty `<style>` element is still appended to the DOM needlessly.

**Fix:** Wrap the render tree in `<CacheProvider value={cache}>` the same way `lis-crs-common-app` does.

### Issue 4 — `lis-request-app` `buildRegistrationTheme` padding stacking (suspected)
**Affected:** `lis-request-app` only.

`buildRegistrationTheme` adds `MuiInputBase.styleOverrides.input: { paddingTop: 6, paddingBottom: 6 }`. This is injected as a later Emotion class after the CMS `getMuiTextFieldTheme()` rule `"& .MuiOutlinedInput-input": { padding: 0 }`, potentially winning at equal specificity and stacking with the wrapper `padding: 12px 8px` to produce ~74px TextField height.

**Status:** Under investigation — theme switch test (ThemeWrapper vs ThemeAwareRoot) showed the problem persists regardless of wrapper, suggesting a different root cause.
